# Modern Business Keynote 风格规范

## 定位

本风格用于现代商用演示：客户方案、项目汇报、商业计划、产品方案、招商介绍、管理层汇报。它可以服务传统企业、政企客户和制造业场景，但不等于老式“传统企业红蓝模板”。

核心目标：

> 现代、商业、可信、清晰、克制、有审美，不土、不旧、不像行政模板。

## 设计原则

1. 商用优先，不以“传统”作为审美限制。
2. Keynote 式表达：少元素、大留白、强观点、强节奏。
3. 现代软件/咨询审美：清晰、轻量、可信、可销售。
4. 红色不是装饰色，只用于风险、警示、异常。
5. 背景不是贴片，而是一页的空间系统。
6. 每页最多一个主要视觉动作：大标题、数据、流程、矩阵、结论，不要同时抢。

## 色彩系统

默认不再使用老式深蓝 + 正红。推荐使用蓝黑、近白、冷灰、电蓝、青色/紫蓝作为商业科技感主轴。

| Token | HEX | 用途 |
|---|---|---|
| `ink` | `#0B1020` | 深色封面/章节背景 |
| `ink_2` | `#111827` | 深色卡片/深色页辅助 |
| `slate` | `#1E293B` | 深色文字/次级深色块 |
| `paper` | `#F8FAFC` | 浅色页背景 |
| `white` | `#FFFFFF` | 卡片/主内容块 |

## 背景系统

### Dark Stage

用于封面、章节、关键结论、结尾。

- 背景为 `ink` 或极深蓝黑。
- 可以有柔和 radial glow，但不能有廉价斜线模板。
- 强调色是蓝/青/紫光感，不用红色顶条。
- 文字白色，副文字冷灰。
- 页面中必须有明确视觉焦点，不要空洞。

### Light Business

用于内容页、卡片页、表格页、目录页。

- 背景为 `paper` 或 `white`。
- 不使用大白圆角容器贴片。
- 用 12 列网格、细线、标签、编号建立结构。
- 卡片轻量、现代，不要老式粗色条。

## 字体系统

- 中文：PingFang SC / Microsoft YaHei / system fallback
- 标题使用 600，不用过黑字重。
- 正文使用 400，颜色用 `body`，避免纯黑压迫。

| 角色 | 字号 | 字重 | 说明 |
|---|---:|---:|---|
| Hero | 38-46pt | 600 | 封面/章节主观点 |
| Page Title | 24-30pt | 600 | 页面标题 |
| Section Label | 10-12pt | 500 | 小型 uppercase/标签 |
| Card Title | 14-17pt | 600 | 卡片标题 |
| Body | 11.5-14pt | 400 | 正文，两到三行 |
| Caption | 8-9pt | 400 | 页脚/说明 |

## 组件规则

### Modern Card

- 白底或半透明深色底。
- 细边框：`line`。
- 圆角可用，但克制。
- 不使用粗左色条作为默认样式。
- 使用小圆点、小编号、短标签表达类别。
- 内容最多 2-3 行。

### Metric / Value Tile

- 大数字或大关键词。
- 一句解释。
- 适合价值页和结果页。
- 不要堆满正文。

### Timeline

- 节点细、线条轻。
- 阶段说明短。
- 深色页可用发光点或蓝色节点。
- 不用老式粗箭头。

### Table / Matrix

- 表头轻量深色或浅蓝底。
- 行距宽松。
- 细线少量使用。
- 不要重边框。

## 文案风格

把旧式行政表达改成现代商业表达。

避免：

- 汇报完毕，请批评指正
- 再创辉煌，共赢未来
- 领导莅临指导
- 大量“稳步推进、压实责任、强化抓手”的堆叠

推荐：

- 让园区运营从经验驱动走向数据驱动
- 以统一数据底座，支撑运营闭环升级
- 从分散管理到统一运营
- 先建立最小闭环，再扩展集成边界

## 禁止事项

- 禁止大面积正红顶条。
- 禁止老式红蓝国企模板感。
- 禁止把“传统企业”理解成过时审美。
- 禁止灰底 + 白色大容器贴片。
- 禁止用斜线装饰伪装科技感。
- 禁止把网页后台卡片直接搬进 PPT。

## Premium Upgrade Rules

当用户反馈“好多了但还不够高级”时，问题通常不在颜色，而在构图、字体权重、图形质量和信息层级。

### 封面高级化

- 封面不是把标题、说明、单位、日期都堆在左侧；必须减少信息层级。
- 标题可以大，但不能像粗黑招牌字；中文标题优先 32-40pt、600 字重，必要时断成 2 行。
- 副标题用更浅的冷灰，字号明显小于标题，避免和标题同样用力。
- 单位/受众/日期等元信息放到底部一行或右下角，不要放成大号三行列表。
- 强调线要细、短、克制；不要用粗蓝条。
- 右侧装饰不能是两个巨大实心圆。高级做法是：低透明光晕、细线轨道、点阵、极淡面状层次，而不是大色块。
- 封面左侧内容区应形成稳定版心，右侧视觉对象应更轻、更有空气感。
- 首页右侧不要做成直白 dashboard 截图感；更优雅的方向是抽象系统场：细环、玻璃面、光点、极淡连接线。文字标签越少越高级，数据线/节点只作为暗示，不要像后台组件。

### 目录与浅色页高级化

- 纯白/近白背景可以是有意设计，但必须有“版心、节奏、留白理由和细节层次”，否则会被看成空白模板。
- 目录页不应只是白底列表。推荐深浅分屏、左侧深色章节舞台、右侧精致目录列表，或用大数字/细线/弱色块建立节奏。
- 目录页必须避免和正文内容页使用同一种深浅分屏结构。若正文第 4 页已使用左深右浅卡片版式，目录页应切到另一种叙事形态，例如全深色空间页、横向轨道节点、漂浮章节、巨型低对比数字，制造 Keynote 式章节过渡感。
- 浅色内容页不要只依赖大白卡片。应使用近白背景、极淡色洗、细分割线、明确版心和少量深色区域形成空间层次。
- 如果用户称“像纯白背景、太基础”，不要辩解为极简；应升级母版，而不是只调卡片边框。

### 图形高级化

- 少用实心几何大块；多用低透明叠层、细线、微光点、网格、坐标、轨道等“精细系统感”。
- 背景图形透明度通常应低于 8%-15% 视觉权重；不能抢标题。
- 不要用粗线、粗条、重边框来制造设计感。
- 所有装饰都应服务“空间深度”和“技术可信感”。

### 内容页高级化

- 不要让卡片像后台 UI；内容页应更像咨询/Keynote 页面：上方一句观点，中部 2×2/3×1 信息结构，底部极轻注释。
- 卡片边框要更淡，标题更短，正文更少。
- 允许使用浅色 panel、编号、细分割线，但避免每张卡都像按钮。
- 每页最多一个强调动作：一个大数字、一条主轴、一组对比或一张矩阵。

## QA Checklist

- [ ] 是否像现代商业演示，而不是老式行政模板？
- [ ] 红色是否只用于风险/警示？
- [ ] 背景是否有空间感，而不是纯色死板填充？
- [ ] 页面是否有明确视觉焦点？
- [ ] 卡片是否轻量、现代、内容克制？
- [ ] 文案是否像商用表达，而不是老式公文？
- [ ] 深色页和浅色页是否有节奏？
- [ ] 传统企业场景是否体现在结构和可信度，而不是土味审美？
- [ ] 封面是否避免了粗蓝条、巨型实心圆、粗黑标题和三行大号元信息？
- [ ] 视觉装饰是否足够精细，而不是简单几何形状堆叠？
- [ ] 是否先进行了架构层优化：页面族、母版、组件层级和 deck rhythm，而不是只对当前页面做局部 patch？
- [ ] 目录、正文、架构、时间轴、价值页是否属于不同页面族，避免全 deck 共享一种卡片/分屏模板？

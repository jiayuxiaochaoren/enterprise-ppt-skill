# Keynote 空间感迭代经验

本参考记录一次从“传统商务模板”迭代到更接近 Keynote 空间感的 PPTX 视觉调优经验，供后续维护 `scripts/generate_pptx.js` 或新增 style profile 时使用。

## 用户反馈信号与对应动作

### “好多了，但还不够高级”

不要只调颜色。常见根因是：

- 标题过粗，像招牌字而不是 Keynote 标题。
- 右侧装饰是大实心圆、粗线或 dashboard widget，显得基础。
- 元信息层级太重，单位/日期/对象抢封面视觉。
- 内容页只有浅灰底 + 白卡片，看起来像后台 UI 或模板初稿。

动作：

- 标题降低字号/字重，增加留白。
- 封面右侧改成抽象系统场：细环、玻璃面、光点、极淡连接线。
- 元信息压到一行，放低权重。
- 内容页使用更明确的版式形态，不要一味堆白卡片。

### “内容页背景太基础，不高级”

纯白/近白可以是高级设计，但必须有版心、节奏、细节层次和视觉焦点。否则用户会理解成“没设计”。

动作：

- 用近白而不是死白。
- 加极淡色洗、细线、页码、页脚和版心结构。
- 让不同页面类型有不同叙事形态：浅色说明页、深色架构页、分屏问题页、空间目录页。

### “目录页和第 4 页重复”

这是页面节奏问题，不是单页美化问题。目录页不能和正文页使用同一种左深右浅结构。

动作：

- 目录页改成 Keynote 式章节转场：全深色舞台、巨型低对比页码、横向轨道、漂浮章节。
- 正文问题页保留左深右浅 + 卡片结构。
- 明确全 deck 节奏：封面 / 空间目录 / 浅色说明 / 分屏问题 / 深色架构 / 深色时间轴 / 浅色价值。

## 文案展示规则

视觉验收稿不要出现：

- 测试
- 示例
- 验收
- 占位
- 待补充

即使是 demo，也要使用真实方案语境，例如：

- `智城云数科技有限公司`
- `园区管委会 / 客户管理层`
- `园区运营数字化升级方案`
- `以统一数据底座，支撑运营闭环升级`

如果需要声明真实性，应在最终回复中说明“这是演示文案/虚构公司名”，不要把说明写进 PPT 画面。

## 验证方式

每次改视觉后至少导出三类预览：

1. 封面：确认右侧视觉是否优雅，不像 dashboard 或大圆装饰。
2. 目录页：确认与正文内容页不重复。
3. 代表性内容页：确认背景不空、卡片不基础、信息层级清晰。

命令模式：

```bash
node ~/.hermes/skills/productivity/traditional-enterprise-ppt/scripts/generate_pptx.js --sample <output.pptx>
qlmanage -t -s 1600 -o <preview_dir> <output.pptx>
```

若需要看非首页页面，生成单页 deck plan 再导出缩略图，避免 QuickLook 只导出首页。

# Executive Keynote 风格解构与可扩展融合规范

## 目标

本规范用于指导 `traditional-enterprise-ppt` 的 PPTX 生成器，不是复制 Apple Keynote，也不是做网页 UI，而是把 Keynote 式的简洁、大气、优雅，融合到传统企业/国企/政企汇报中。

最终目标：

> Executive Keynote for Traditional Enterprise：深蓝主视觉、留白充足、文字克制、组件一体化、页面节奏清晰、适合领导/客户汇报。

## 可扩展风格架构

后续可能继续解构并融入其他风格，因此不要把生成器硬编码成单一 Keynote 风格。每种风格都应沉淀为一个 style profile。

每个 style profile 至少包含：

1. `design_intent`：适合什么场景，不适合什么场景。
2. `background_system`：背景如何构成，哪些页面用深色，哪些页面用浅色。
3. `color_tokens`：主色、辅助色、中性色、强调色、文字色。
4. `typography`：标题、章节、正文、脚注的字号/字重/色彩。
5. `layout_principles`：网格、留白、版心、信息密度。
6. `components`：卡片、时间轴、目录、表格、指标块等组件规则。
7. `do_not`：明确禁止的视觉习惯。
8. `qa_checklist`：生成后如何判断视觉是否合格。

生成器应支持类似：

```json
{
  "style": "executive-keynote",
  "tone": "traditional-enterprise",
  "slides": []
}
```

如果用户以后要求其他风格，例如“华为发布会风”“麦肯锡咨询风”“国企党建风”“招商路演风”，应新增 style profile，而不是破坏 Executive Keynote 的基础规则。

# Style Profile: executive-keynote

## 1. 设计意图

适合：

- 企业战略/项目/年度汇报
- 政企/国企/传统企业客户方案
- 高层汇报、审批材料、招商介绍
- 希望“简洁、大气、优雅”，但仍需要商务稳重的 PPT

不适合：

- 信息密度极高的财务明细表
- 党建红色主视觉材料
- 发布会级强视觉动画
- 强互联网营销风

核心关键词：

- 简洁
- 大气
- 克制
- 稳重
- 高级留白
- 强标题层级
- 一页一个核心观点

## 2. Keynote 风格反向解构

Keynote / Apple 式表达的核心不是装饰，而是“舞台感”：

- 背景是一个完整舞台，不是多层贴片。
- 大量留白让内容显得重要。
- 颜色预算很少，通常一个主色 + 一个强调色。
- 字体层级比线框和阴影更重要。
- 卡片不是网页组件，而是被放在舞台上的信息对象。
- 每页只讲一个核心意思，文本不堆满。

可借鉴：

- 深浅页面节奏：深色页用于情绪和重点，浅色页用于信息解释。
- 大标题 + 短正文：标题承担观点表达，正文只补充。
- 单一强调色：强调色只服务重点，不平均分配给每张卡片。
- 高级留白：内容不要填满全屏。

不可照搬：

- 不要做成纯 Apple 发布会。
- 不要过度使用黑色、产品摄影、蓝色 CTA。
- 不要牺牲传统企业汇报所需的结构感和可信度。

## 3. 背景系统

背景必须是“母版系统”，不是“蓝条 + 灰底 + 白卡贴片”。

### A. Deep Blue Stage 深蓝舞台页

用于：

- 封面
- 章节页
- 结尾页
- 核心结论页
- 重要实施路径页

结构：

- 整页深蓝背景。
- 可加入极淡几何线条、斜切块、半透明大圆或网格，但透明度必须低。
- 白色/浅蓝文字。
- 内容块可以是白色或半透明深蓝，但必须像舞台中的主对象，不是网页卡片。

推荐 token：

- `bg_deep`: `#0F2E4D`
- `bg_deeper`: `#0A223A`
- `bg_panel_dark`: `#123B63`
- `text_on_dark`: `#FFFFFF`
- `text_muted_dark`: `#D9E6F2`
- `accent_red`: `#C00000`
- `accent_gold`: `#B38B00`

### B. Clean Executive Light 清爽商务页

用于：

- 目录
- 背景说明
- 痛点页
- 模块矩阵
- 风险表格
- 详细内容页

结构：

- 背景使用纯白或极浅暖灰/蓝灰。
- 不再叠大白色圆角容器。
- 如果需要承载区，用清晰的版心和线条实现，不用网页卡片感。
- 顶部/左侧可以用深蓝结构条，但必须是母版的一部分。

推荐 token：

- `bg_light`: `#FFFFFF`
- `bg_soft`: `#F5F7FA`
- `text_primary`: `#12365D`
- `text_body`: `#4A4F55`
- `line`: `#D9E2EC`
- `panel_soft`: `#F3F7FB`

### 禁止背景做法

- 不要在深蓝背景上再贴一层灰，再贴一层白。
- 不要使用“网页后台”式大白圆角容器。
- 不要让顶部深蓝条成为唯一背景元素。
- 不要通过“改浅灰”来假装背景有设计。

## 4. 色彩系统

颜色必须有权重，不要平均分散。

推荐比例：

- 主色：70% - 85%
- 中性色：10% - 25%
- 强调色：3% - 5%

### 默认配色

| Token | HEX | 用途 |
|---|---|---|
| `navy` | `#0F2E4D` | 深蓝舞台背景、标题栏、重点块 |
| `navy_2` | `#12365D` | 标题、结构线、模块头 |
| `blue` | `#1E4D78` | 次级强调、节点、信息块 |
| `white` | `#FFFFFF` | 深色背景文字、浅色内容块 |
| `soft_bg` | `#F5F7FA` | 浅色页背景 |
| `soft_panel` | `#F3F7FB` | 轻信息块背景 |
| `line` | `#D9E2EC` | 分割线、弱边框 |
| `body` | `#4A4F55` | 正文 |
| `red` | `#C00000` | 风险、第一阶段、关键提醒 |
| `gold` | `#B38B00` | 成果、价值、关键数字 |

### 强调色规则

- 每页最多 1 个强调色。
- 红色用于风险、关键节点、第一阶段，不要每张卡片一个颜色。
- 金色用于成果/价值，不要和红色在同一页抢主视觉。
- 不要红、蓝、绿、金平均散落。

## 5. 字体系统

Keynote 式高级感很大程度来自字体层级，而不是装饰。

推荐字体：

- macOS：`PingFang SC`
- Windows：`Microsoft YaHei`
- fallback：`Arial`, `sans-serif`

### 字号层级

| 角色 | 大小 | 字重 | 颜色 | 说明 |
|---|---:|---:|---|---|
| 封面标题 | 40-48pt | 600-700 | 白/深蓝 | 一页主角 |
| 章节标题 | 34-40pt | 600 | 白 | 深蓝页使用 |
| 页面标题 | 24-30pt | 600 | 深蓝/白 | 不要过粗 |
| 模块标题 | 15-18pt | 600 | 深蓝 | 卡片标题 |
| 正文 | 12.5-15pt | 400 | 深灰 | 控制在 2-3 行 |
| 注释/页脚 | 8-9pt | 400 | 灰/浅灰 | 不抢视线 |

原则：

- 标题可以大，但正文要克制。
- 不要所有文字都加粗。
- 正文不要黑得太重，使用深灰。
- 页面标题不靠红色竖条硬撑层级，应靠字号、位置、留白建立层级。

## 6. 页面节奏

10 页默认节奏建议：

1. 封面：Deep Blue Stage
2. 目录：Clean Executive Light
3. 背景：Clean Executive Light / 两栏
4. 痛点：Clean Executive Light / 2×2 信息块
5. 架构：Deep Blue Stage 或 Light / 一张主图
6. 模块：Clean Executive Light / 3×2 矩阵
7. 路径：Deep Blue Stage / 横向阶段图
8. 价值：Clean Executive Light / 大 Tile
9. 风险：Clean Executive Light / 表格矩阵
10. 结尾：Deep Blue Stage

不要 10 页都长一样。

## 7. 组件系统

### Executive Block 传统企业信息块

用途：痛点、举措、模块、风险。

结构：

- 主体矩形或极小圆角。
- 左侧色带可保留，但必须一体化。
- 色带高度 = 卡片高度。
- 色带和主体共用 y/h，不允许独立漂浮。
- 标题和正文都在主体内部。
- 不同时叠加“左色带 + 横向标题底色 + 阴影 + 大圆角”。

推荐：

- 主体：白色或 `#F8FAFC`
- 左色带：深蓝或单页强调色
- 边框：`#D9E2EC`
- 圆角：0 或极小
- 阴影：无或极轻

### Keynote Tile 大留白信息块

用途：价值页、能力页、总结页。

结构：

- 大块留白。
- 一个大数字/关键词。
- 一句结论。
- 不使用复杂边框和色条。

### Timeline Stage 阶段页

用途：实施路径、阶段计划。

结构：

- 节点和阶段内容严格对齐。
- 阶段节点可以用圆形编号。
- 阶段内容块要统一宽高。
- 第一阶段可红色，其余深蓝。
- 连接线细、淡，不抢视觉。

### Table / Matrix 表格页

用途：风险、责任、计划。

结构：

- 深蓝表头。
- 白色或浅灰表体。
- 行高宽松。
- 只保留必要线条。
- 不使用复杂阴影。

## 8. 禁止事项

- 不要用灰底 + 白色大圆角容器模拟背景。
- 不要把左侧色块错了就全部改成横向色条。
- 不要多个 shape 拼出一个看似卡片的组件，除非严格对齐并经过视觉验证。
- 不要用重阴影制造高级感。
- 不要把 Web UI 的 card 组件搬到 PPT 里。
- 不要每页都使用同一个卡片组件。
- 不要让强调色平均分散。
- 不要把正文堆满卡片。

## 9. QA Checklist

生成后逐页检查：

- [ ] 这一页是 Deep Blue Stage 还是 Clean Executive Light？背景逻辑是否单一？
- [ ] 是否存在“蓝色背景 + 灰色贴片 + 白色贴片”的多层补丁感？
- [ ] 是否像网页后台 UI，而不是 PPT 汇报？
- [ ] 页面是否有明确视觉主角？
- [ ] 标题、正文、注释层级是否清楚？
- [ ] 每页强调色是否不超过 1 个？
- [ ] 信息块是否一体化？有没有外挂色条/错位色块？
- [ ] 卡片正文是否控制在 2-3 行？
- [ ] 深色页和浅色页是否形成节奏？
- [ ] 是否仍然符合传统企业稳重、清晰、可信？

## 10. 后续可扩展风格占位

后续可继续新增：

- `consulting-mckinsey`：咨询汇报风，强调金字塔逻辑、图表、极简黑白蓝。
- `state-owned-red`：国企/党建/政策宣贯，强调红金、庄重、标题对仗。
- `huawei-launch`：科技发布会风，强调深色、光效、产品/方案舞台。
- `investment-roadshow`：招商/融资路演风，强调故事线、数据、愿景。
- `industrial-manufacturing`：制造业工程风，强调蓝灰、流程、现场照片、指标。

每个新风格都必须独立写 style profile，再映射到母版和组件，不要直接在 Executive Keynote 上叠补丁。

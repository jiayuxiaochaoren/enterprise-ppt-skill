# PPTX 布局与背景 QA 经验

本参考用于维护 `premium-commercial-ppt` 的内置 PPTX 生成脚本，尤其是 `scripts/generate_pptx.js` 的默认母版、卡片页和内容页布局。

重要：本文件只记录已踩过的布局问题和 QA 方法。真正的视觉方向以 `references/keynote-executive-style.md` 为准；不要把本文件理解为“固定浅灰背景 + 白色容器”的设计规范。

## 背景丢失感的真实根因

真实生成 `.pptx` 后，即使文件结构和文本验证都通过，视觉上仍可能不合格。典型表现：

- 内容页只有顶部深蓝条，主体区域近乎纯白。
- 背景没有形成完整母版，只剩一条装饰色带。
- 或者为了修背景，又叠加浅灰底、大白色圆角容器、卡片阴影，结果变成网页后台 UI。
- 用户会直观认为“背景是不是丢失了”或“这不是原本蓝色背景”。

这不是 PPTX zip 或文字生成失败，而是母版系统没有建立。背景应是一个完整舞台或完整汇报版式，不是通过灰白贴片补出来。

## 背景 QA 原则

每一页只能选择一种背景逻辑：

1. Deep Blue Stage：整页深蓝背景，适合封面、章节、重点结论、时间轴、结尾。
2. Clean Executive Light：整页白/近白背景，深蓝结构线和清晰版心，适合目录、信息页、表格页。

禁止：

- 蓝色背景上再贴灰色，再贴白色，再贴卡片。
- 用大白色圆角容器模拟 PPT 背景。
- 只保留顶部蓝条，把主体留成无设计的白/灰空地。
- 用浅灰色替代真正的背景设计。

## 色块与卡片 QA 原则

用户指出左侧色块“分裂、不对齐”时，不要简单把所有竖向色块改成横向色条。这只是规避一个渲染问题，不是设计解决方案。

正确判断：

- 如果使用左侧色带，它必须是卡片结构的一部分。
- 色带与卡片主体必须共用 x/y/h 逻辑，高度一致、边界一致。
- 卡片不要同时叠加：左色带 + 横向标题底色 + 圆角主体 + 阴影；这些 shape 在 PPTX 渲染中容易出现 1px 错位。
- 传统企业风格可用直角或极小圆角信息块，让左色带自然成为一体化结构。
- 如果改用顶部色带，必须是当前 style profile 的组件规则，而不是为逃避左色带问题的全局替代。

## 卡片页布局规则

3×2 卡片页最容易出问题。避免：

- 卡片高度太小。
- 两行卡片集中在页面上半部分。
- 下半屏大面积空白。
- 卡片像 SaaS/Web UI 组件。
- 强调色平均分散到每张卡片。

应做到：

- 卡片或信息块占据页面中部到中下部，但保留足够呼吸感。
- 每页强调色不超过一个；不要红、蓝、绿、金平均散落。
- 卡片正文控制在 2-3 行。
- 卡片样式应匹配页面母版：深蓝页用高对比块，浅色页用干净信息块。
- 不同页面类型使用不同组件，不要一套卡片硬套所有页面。

## 验收方式

文件级验证必须分两层：

1. 结构验证：`validate_pptx.js` 检查文件、页数、zip、中文文本、必含关键词。
2. 视觉验证：打开 PPTX 或用 QuickLook/PowerPoint/Keynote 截图检查至少封面、目录、卡片页、时间轴页、结尾页。

结构验证通过不代表视觉通过。用户指出“布局不太行”“背景是不是丢失了”时，应优先检查母版系统和组件规则，而不是怀疑内容策划或 PPTX 文件损坏。

## 修复方向

当卡片页或内容页看起来太素、太像网页 UI、背景不对时，优先改：

- style profile：先明确这一页应该属于 Deep Blue Stage 还是 Clean Executive Light。
- 母版函数：背景、标题区、页码、页脚、版心。
- 组件函数：信息块是否一体化、色带是否与主体对齐、是否滥用阴影和圆角。
- 页面分支：卡片宽高、起始 Y、横纵间距、intro/note 的承载方式。

不要只调文字大小、颜色或把竖色条改横色条；根因通常是母版和组件系统没有定义清楚。
